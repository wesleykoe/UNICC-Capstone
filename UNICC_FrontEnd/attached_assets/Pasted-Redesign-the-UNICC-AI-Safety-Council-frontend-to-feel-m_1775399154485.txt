Redesign the UNICC AI Safety Council frontend to feel more executive-friendly, presentation-ready, and decision-oriented for a UN demo.

Goals:
1. Make the product feel like a decision support platform, not an engineering dashboard.
2. Improve clarity, hierarchy, spacing, and readability.
3. Keep the overall blue/white enterprise style, but make it cleaner and more premium.
4. Do NOT add dark mode.
5. Keep the existing tabs: Dashboard, Run Evaluation, Expert Panel, Council Decision, Reports.
6. Remove unnecessary technical clutter and prioritize decision clarity.

Key UX changes:

A. Dashboard
- Replace the current top metrics with 4 executive summary cards:
  1) Final Decision
  2) Final Risk Level
  3) Primary Risk Driver
  4) Human Review Status
- Make the latest evaluation the center of attention.
- Reduce emphasis on "total evaluations" and "active experts".
- Add a "Latest Council Outcome" hero card with:
  - final decision badge
  - one-line meaning
  - top 2 reasons
  - CTA buttons: View Decision, View Report

B. Run Evaluation
- Keep the AI Agent field.
- Improve the scenario section with better spacing and labels.
- Add "Quick Scenario Templates" above the textarea:
  - Political Pressure Test
  - Data Leakage Test
  - Harmful Output Test
- Keep expert module checkboxes, but style them as premium selection cards.
- Keep the interface simple and guided.

C. Expert Panel
- Redesign each expert card so it is easier to understand in 3 seconds.
- Show:
  - status badge
  - risk badge
  - action badge
  - confidence badge
  - one-line human-friendly interpretation
  - key finding
  - framework references
  - human review required or not
- Use clear color coding:
  - green for pass/approve
  - amber for caution/revise
  - red for fail/reject
  - blue/gray for neutral metadata
- Make cards more spacious and polished.

D. Council Decision
- This page must become the strongest page in the product.
- Add a large hero decision card with:
  - decision icon
  - final decision
  - one-line deployment meaning
  - final risk
  - experts completed
- Below that, add 3 structured sections:
  1) WHY THIS DECISION
  2) OPERATIONAL IMPACT
  3) REQUIRED NEXT STEPS
- Add an "Explainability / Arbitration" section that shows:
  - Governance Expert -> action
  - Threat Expert -> action
  - Behavioral Expert -> action
  - Applied rule, such as: Any Reject -> Final Reject
- Make the decision rationale more human-readable and less technical.
- Add better visual separation and spacing.

E. Reports
- Keep the table, but improve spacing and typography.
- Make selected report details feel like an executive summary, not a log dump.

Design system requirements:
- Rounded cards (16px to 20px)
- Softer borders
- Better shadows
- More whitespace
- Stronger typography hierarchy
- Larger page titles
- Better spacing between sections
- Use Lucide icons where appropriate
- Keep everything presentation-friendly and professional

Technical requirements:
- Use React + TypeScript
- Use Tailwind classes
- Keep the existing data structure if possible
- Refactor repeated UI into reusable small components
- Create helper functions for:
  - risk badge styles
  - decision badge styles
  - status icons
  - decision explanation text
- Do not break the current tab navigation
- Do not remove current functionality

Important:
- The UI should feel suitable for a UN or humanitarian governance demo.
- The tone should be trustworthy, clear, and restrained.
- Prioritize "why, impact, action" over raw technical details.
